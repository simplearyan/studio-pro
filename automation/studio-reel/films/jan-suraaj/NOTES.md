# JAN Suraj — NOTES

The second film, and the first one authored from **someone else's design** rather
than from a film we already had. This file is the answer to "how hard is it, and
how do we make the next one easier".

Verdict up front: **the content is easy and the design is the whole problem.**
35 of 35 elements compiled, 9 of 9 scenes, 70 seconds — and the gate exited
**green** while the output looked nothing like the brand. Details below.

## 2. The measurement

`node automation/studio-reel/reel-compile.cjs --only jan-suraaj` → **EXIT 0**
"every authored element compiled". The rendered film is wrong anyway.

| brand requirement | what the film actually shows |
|---|---|
| `Bebas Neue`, `Khand`, `Hind` | **none present.** The emitter's runtime names only Inter, JetBrains Mono, Literata |
| hard shadows `8px 8px 0 #000` | **zero.** `grep -c 'box-shadow:Npx Npx 0'` → 0 |
| `radius: 0` (square) | **rounded**: `1.1vw`, `1vw`, `6vw` all over the output |
| dot-grid background | **flat** `#0e1512`, the emitter's default. All 9 scene backgrounds discarded |
| saffron/green/blue per scene | meters render cyan; the palette never reaches the film |
| `2px solid #000` borders | `1px rgba(255,255,255,.09)` |
| rotated sticker labels | no rotation anywhere |

Devanagari is the one pleasant surprise: the characters **do** render, because
the host system supplies a fallback face. But it is a generic serif, not Khand,
so the brand's voice is absent even where the script works.

**So: content fidelity 100%, design fidelity roughly 10%.**

## 3. Why the gate went green

`reel-compile` checks structure — duration, scene count, empty wrappers,
timeline coverage. It has no opinion about whether a film *looks* like anything,
because until now every film came from the one design the emitter was written
against. The gate is doing its job; the job was simply smaller than the question.

This is the trap worth naming: **a green structural gate on a second design is
false comfort.** The `design` block in `storyboard.json` is invisible to it —
not warned about, not measured, just dropped.

## 4. The three things that block arbitrary designs

1. **The theme is baked into `RUNTIME_CSS` as string literals.** One design
   language — rounded glass panels, soft shadows, one flat background, three
   fonts. There is no seam to inject a second one.
2. **The clip has no `fonts` field.** `compileStoryboard` returns
   `{name, dur, ds, html, css, js}`. A brand needs its own webfonts loaded;
   `StudioPro.fonts.loadGoogleBatch()` exists in the composition API but the
   storyboard path never reaches it. Any film needing a font the runtime does
   not name is unrenderable.
3. **Per-scene background is one flat colour.** Even a design that only wanted a
   colour change per act cannot have it.

## 5. What to build, in order

This is the same order that worked last time: make the gap measurable first,
then close it.

1. **A `theme` object that the emitter reads**, emitted as CSS custom properties
   on `.hss`: `--hss-radius`, `--hss-shadow`, `--hss-border`, `--hss-font-display`,
   `--hss-font-body`, `--hss-font-mono`, plus the eight brand colours. The five
   element types I added last turn already read colours from `--hss-*`, so they
   are already themeable — the *defaults* are what is hardcoded.
2. **`fonts` on the clip**: a `fonts: [{family, href}]` field, emitted as a
   `<link>` in `buildStandalonePage` and passed to `loadGoogleBatch` in the
   editor. Unblocks Devanagari and every non-default brand.
3. **Per-scene `background`**, including a `dots`/`blueprint` pattern type, so a
   scene can change mood. This is what makes multi-act films possible.
4. **A `style` per element** (`display` / `body` / `label`) so a brand's role
   names mean something, instead of `size: title|sub|body`.
5. **Then** teach `reel-compile` to fail when an authored `design` field is
   dropped — the missing check from §3.

## 6. Making it work from a URL

The user-facing question was "can we take a site URL and get a film in that
design". Decomposed, this is mostly already solved in pieces:

- **Extract** — fetch the page, read the computed styles of the distinctive
  elements, pull the palette from `tailwind.config`/`theme()`/CSS variables, and
  the font `<link>`. This is mechanical and `Design.md` §1–5 is the output shape.
- **Classify** — name the style (neo-brutalist, glassmorphism, editorial,
  swiss) and map it onto theme tokens. This is the judgement step, and it is
  where an LLM helps: naming a design language from a screenshot is a
  recognition task, not a measurement.
- **Author** — tokens + content into `storyboard.json`, which already works.
- **Compile** — `reel-compile`, which already works.

So the pipeline is: **URL → Design.md → storyboard.json → reel → render.** Two of
the four stages exist. The two that do not are the extractor and the classifier.

The honest sizing: extraction is a day. Classification plus a theme layer in the
emitter is the real work — and the theme layer is worth doing on its own merits,
because it is also what makes the first film (breath-of-air) authorable without
hand-writing CSS.

## 7. What is deliberately not done

No attempt was made to force the film to look right by inlining CSS into the
scene, or by degrading the brand to what the emitter supports. Both would make
the gate green and the film wrong in a way nobody would notice. The gap is
recorded instead.
