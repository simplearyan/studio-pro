# Prompt stability & variation — plan

**Status:** plan. Nothing here is built yet. Every claim about the failing clip
below is quoted from the file itself, not assumed.

## 0. Symptom

A long animation generated by Claude from the current prompt (the user's
`Clip_Flow_Canvas_Long_code.json`, 15 s, 4 boards) shows **text flickering its
position** — captions and typed lines teleport a few pixels at scene changes.
The clip is otherwise good: deterministic time math, a keyframe table, guarded
lookups. The flicker is not sloppiness — it is exactly what the current
HARD CONTRACT (rules 1–7) never mentions, so the model had no way to know.

## 1. Root causes (measured from the failing file)

| # | What the code does | Where | Why it flickers |
|---|---|---|---|
| 1 | `c1.textContent = CAPS[idx][1]` + `display:inline-block/none` on swap | `onFrame`, captions block | The caption pills (`.cl`, `inline-block` with padding) live in `#cap { width: 800px; text-align: center }`. Every caption swap changes the string → the pill's width changes → **re-centering teleports the whole line horizontally**. A 15 s clip has many swaps, so the flicker repeats. |
| 2 | `cct.textContent = str + caret` every frame; caret blinks by toggling a `▏` appended to the string | `onFrame`, typed text | Content rewrite per frame. The fixed 160 px box keeps this one *mostly* stable, but any container without an explicit width would jump on every caret toggle — and the contract doesn't require the fixed box that saved it. |
| 3 | `ck.style.width = w` and `hnd.style.left = …` animated per frame | `onFrame`, trim board | Animating **layout properties** (`width`, `left`) instead of `transform`. Here they are absolutely positioned so the damage stayed local — but the pattern, in flow layout, shifts every sibling text on every frame. |
| 4 | `lastCap` module-level mutation to skip caption rewrites | module scope + `onFrame` | Stateful `onFrame`: correct only if the renderer never seeks out of order. The contract's "same t in = same frame out" is about time math; it never said *onFrame must be pure*. |
| 5 | Rule 3 hardcodes `800 x 450` regardless of the `<!-- ds:9:16 -->` marker | prompt contract | A 9:16 request arrives with 16:9 instructions; the model improvises the canvas and inherits every layout assumption wrongly. |
| 6 | `CLIP DURATION: N ms` with no pacing guidance, and the model stretching time by a private scale (`t = clamp(raw / 2.6, 0, 5000)`) | prompt contract | The duration label lies (caught today only by the editor's auto-detection probe), and long clips collapse everything onto one timeline — which multiplies every instability above. |

## 2. What the clip did *well* (mandate it, don't only forbid)

- **One timing table per concern** (`CAM`, `CUR`, `CLICKS`, `CAPS`) with a pure
  `seg`/`prog` searcher — this is why the choreography reads cleanly at all.
- **Guarded lookups** (`var el = $("x"); if (el) …`).
- **`setO(el, opacity, transform)`** — a single writer for the two safe
  properties, used almost everywhere.
- **Fixed-width text box** (`#cct { width: 160px; white-space: pre }`) — the
  reason the typed line survives; the contract should require this everywhere.

## 3. Contract additions (exact text for `CONTRACT_RULES`)

Add as rules 8–12; the numbering continues the existing HARD CONTRACT block.

```
8. Purity: onFrame(time) must be a pure function of time — no module-level
   mutable state, no counters, no "did I already do this" flags. Two calls
   with the same time, in any order, must render identically.
9. Never mutate text after the first paint: no textContent, innerHTML,
   create/append/remove inside onFrame. Build the whole DOM once at module
   load. Typewriter effects: pre-split the string into one <span> per
   character at load time, then animate each span's opacity from time.
10. Every text container gets an explicit width AND height in the CSS, with
    the text centered INSIDE that fixed box. If captions or labels swap
    content, either pre-render every variant as its own node and crossfade
    by opacity, or swap inside a fixed-size box so its width cannot change.
    A blinking caret is its own fixed-width span (width:0.55em) toggled by
    opacity — never appended to the string.
11. Animate transform and opacity ONLY. Never write width, height, left,
    top, margin, font-size or background-size from onFrame. Growing bars use
    transform: scaleX() with a transform-origin; moving handles live in a
    fixed-size wrapper moved by translate().
12. Length discipline: every timing lives in one table at the top (arrays of
    [startMs, endMs, …]) interpreted by pure helpers; timings must span
    exactly the declared CLIP DURATION — do not invent a private time scale
    or rescale time inside onFrame. Scenes that have finished get
    display:none from time math (keeps the per-frame raster small). Keep the
    total DOM under ~150 nodes.
```

## 4. Variation axes (style · length · aspect)

- **Aspect** — make rule 3 *generated*: `buildFullPrompt` emits the design
  space from the frame bar's aspect (the same `curFrame`/`dsDims` source of
  truth the renderer uses) instead of the hardcoded "800 x 450":
  `16:9 → 800×450`, `9:16 → 450×800`, `1:1 → 720×720`, `4:5 → 640×800`.
  Changing the frame bar re-runs `refresh()`, so the LIVE PROMPT follows.
  The ds marker line joins `<title>` in the OUTPUT FORMAT example so the
  model knows it may emit it (16:9 stays marker-free — the parser defaults).
- **Length** — the CLIP DURATION line gains a pacing table:
  `≤5s: 1–2 scenes · 5–15s: 3–6 scenes · 15–60s: chapters every 6–10s ·
  >60s: loop-safe structure`. This is guidance, not a new module — duration
  already typeable to 600 s.
- **Style** — rides the existing modules (Format archetype, Typography,
  Palette, one-line intent). The contract only adds one rule-adjacent line:
  pick ONE motion language (one easing vocabulary) and keep it for the whole
  clip. No new module needed; the brief budget absorbs ~1.5 k chars.

## 5. Implementation outline (`prompts-engineer.html`)

1. `CONTRACT_RULES` (array at `prompts-engineer.html:508`): append rules
   8–12 verbatim from §3.
2. Rule 3 + the `800 x 450` line in CONTRACT_RULES become a small function of
   the parsed ds marker (`buildFullPrompt(want, dur, ds)`), defaulting to
   16:9 exactly as today when no marker is present.
3. The CLIP DURATION line (`prompts-engineer.html:527`) appends the §4
   pacing table and the "no private time scale" clause (rule 12 repeats it;
   the duration line is where the model looks first).
4. The OUTPUT FORMAT example (`:529`) gains `<!-- ds:9:16 -->` next to
   `<title>` with a comment "omit for 16:9".
5. `BRIEF_BUDGET` is 6 000 chars (`:756`) — the contract grows ~1.5 k, so
   briefs stay under budget, but confirm the char badge and the
   over-budget threshold still behave.

## 6. Verification

1. Re-ask Claude with the hardened prompt for the same brief; paste the reply
   into the PE preview rail — scrub across caption swaps and the typewriter
   window: no horizontal jumps.
2. Import the reply into test-renderer — the authored-length probe adopts the
   true duration (regression: the 5 s-declares-15 s case) and the contract's
   rule 12 should make the probe and the label agree without intervention.
3. Seek-scrub backwards through caption scenes (purity check): captions must
   re-render at every seek, never depend on visit order.
4. Determinism: the reel gate's double-run probe still passes on a compiled
   storyboard (no regression from rule text changes — the gate never reads
   the prompt, but the storyboard compiler's own output should be spot-checked
   against rule 9's pattern).
5. **Phase 2 (optional tooling):** a flicker detector — render t and t+33 ms
   pairs during *declared hold windows* and diff; nonzero diff where the
   timeline says nothing moves = flicker. Not required to ship the prompt.

## 7. Non-goals

- No renderer changes — this plan hardens the *instructions*, the raster path
  stays as is (the editor's auto-duration probe already handles label lies).
- No new PE modules; style variation rides existing modules.
- No changes to the automation contract (named globals/ids untouched).
