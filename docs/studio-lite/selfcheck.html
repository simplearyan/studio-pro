Clip Lite — self-check

Every Adjust knob and every filter, measured against a synthetic frame that has a known flat field, known step edges and known colour patches. Each control has to prove three things: it is exactly a no-op at its rest (which is 1, not 0, for Opacity), it moves its own metric in the direction its name promises, and — for the spatial controls — it still does that after the picture is scaled down to the size the preview actually shows.

How this measures

The frame. A 720×1280 synthetic chart at the mock's real backing size: a flat #808080 field, step edges of 1px, 2px and 3px, six flat colour patches, a highlight patch, a shadow patch and a mid-grey plate in the centre. Synthetic because it is deterministic — the same chart every run, on any machine, with no media file and no decoder in the way.

The pipeline is not reimplemented. The mock is loaded in an iframe and this page calls the real look() and the real frameStage() inside it. A copy of the filter strings would only prove the copy works; these numbers come from the code that ships.

Measure what the user sees. Sharpen shipped as contrast() saturate() and scored +9% acutance at full resolution while scoring −5% as displayed — 720px of canvas shown in 257px gets averaged by the browser, and averaging cancelled the boost. The control was making the picture softer and the readout said otherwise. So every control is measured twice: on the canvas, and again after a 2.8× downscale. A control whose two answers disagree in sign is flagged, because that is the failure mode that hides.

Filters — eleven chains and two layers

The eleven looks are chains: one of them can be on, at its own strength. Vignette and Grain are not chains — they are layers drawn after the frame, over whichever chain is picked, each with its own strength. So each layer is measured twice: once on a bare clip for its own signature, and again on top of a graded clip, because a layer that quietly replaced the grade would still pass the first test.

Shelf rows hold their place

A tap must not move the row it was on. Picking a look rebuilds the row — the strength slider appears with it — so the scroll offset has to survive that rebuild, and the sheet may re-centre only a selection it did not get from a tap. Each row below is scrolled to an offset, a card is tapped, and the offset is read back. The last row is the opposite assertion on purpose: a rebuild nobody tapped for still has to bring an off-screen selection into view, so a "fix" that simply switched centring off fails here rather than passing quietly.

The sheet's geometry

A layout cannot be read off a pixel or a filter string. The value could sit forty pixels above its slider and still be "the readout"; the footer's middle action could drift left and still be "three buttons"; a centre dot could appear on every slider and still be "a dot". Each of those is a promise the restyled sheet makes, and only geometry can see it — so these run as measurements, in the same phone-sized instance the row checks use, because a layout claim only means something at a laid-out width.

The clip actions, and the slider under the thumb

Reverse, Replace, Rearrange and Delete act on the clip that is selected, not on its look — so no filter string and no pixel can see them, and a rule that moves the wrong clip or loses the edit would look exactly like a rule that works. Each is driven the way a finger drives it: a real tap on the real rail button, a real pointer drag over the real card. The order test is the one that catches a rename: the four actions have to sit together on the rail and in the reference's own order. The last row is the one value claim no pixel can see either — that the readout and the knob's changed-dot follow the thumb on every input, mid-drag, rather than settling when it comes up.
