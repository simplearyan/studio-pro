Studio Lite · design mock

The phone-shaped path through the same project file

A second app over the same core — not a narrow window on Studio Pro. Every decision here is traceable to docs/STUDIO-LITE-PLAN.md: the layout tiers are §6.1, the gesture and ergonomics rules are §5, the feature scope is §3, and the palette is the shared Material 3 layer from hic-theme.css.

Start at section 2 — five phone screens showing the timeline with video, audio, text and HTML-in-canvas clips, and what a trim handle looks like when it is built for a thumb.

1 · The app, at all three tiers

All three panels are the same markup. The layout is chosen by the panel's own width (CSS container queries), so a 390px panel shows the phone layout even on a wide screen. On the phone the timeline is always on screen and the sheet stays parked until you ask for it — scrub the ruler, drag a clip, tap the dock, drag the sheet grip.

Anatomy · one handle, one home

Clean trim handles

▶Screen demo2.4s
2.4s 1 2 3 4
  1. 1The bar you see. 10–12px wide, inset from the clip edge — never centred on it, so your thumb cannot cover the cut it is making.
  2. 2The target you hit. 44×44 minimum, drawn around the bar. Toggle Show hit targets: the dashed area is bigger than the clip on purpose.
  3. 3The body moves, the edge trims. Dragging the middle slides the clip between lanes; dragging a handle only changes in/out. Two gestures, never one ambiguous one.
  4. 4Live feedback. A snap guide and a duration bubble appear while trimming and leave with the gesture — plus one undo entry per drag, not per frame.

Handles are rendered as siblings of the clip, not children: a child is clipped by the clip's own overflow: hidden and quietly loses most of its 44px target. And a handle only exists while its clip is selected — the strip is a timeline, not a wall of grab bars.

One grammar, four kinds

A lane's texture is its kind, so a strip stays readable at 20px tall and in greyscale. Every texture is a CSS gradient — no image asset, no network request, and both themes come from the same rules.

Borrowed from YouTube Create — and refused

It is the reference for "an editor built for a phone, not shrunk onto one". What it does well is worth copying; what it does to fill a screen is not, because lite opens your project.

Taken

  • Strip always visible; the preview never owns the whole screen
  • One kind per lane, colour-coded, no track menus on a phone
  • Primary actions in the bottom 40%, thumb first (§5.3 rule 7)
  • Edge-to-edge stage, so the frame is the brightest thing on screen

Refused

  • A template feed on launch — lite opens your project (§2.2 J1)
  • A licensed music library — audio comes from your files
  • Auto-captions as the front door — still here, as a clip, not a screen
  • Filters and effects — that is Pro's job (§2.3)

3 · Palette

One set of roles, light and dark. Interactive colour is reserved for the selection, the playhead and the active destination — everything else is surface and ink, which is what keeps a dense editor calm. Toggle the theme above: every swatch below is a live token read, not a picture of one.

6 · Feature concepts

Lite is scoped by three jobs, not by feature parity. If a feature is not required for one of these, it stays in Studio Pro — which is what keeps this shell small enough to be fast on a phone.

J1 · Highest value

Open and finish

Open a project — yours, or a .spcomp from Pro — change some text or a picture, fix the timing, export. This is what you do away from the desk.

J2

Build a short from scratch

Add text/shape/image/HIC clips, type a Markdown script and generate slides, caption it, pick an animation preset, arrange a small timeline, export 9:16.

J3

Capture and go

Import from the camera roll, trim it, caption it, export, share.

The dock is the whole navigation

Four destinations replace Pro's six-tab sidebar, each one a thumb-height away in the bottom 40% of the screen. Panels arrive as a sheet that drags between 50% and 92% and dismisses downward — never a permanent panel stealing the stage.

  • Clips — the list and track order
  • Inspect — properties for the selection
  • Add — text, shape, image, video, audio, captions, Markdown
  • Export — format, resolution, fps, range, progress

One gesture layer, three inputs

Pointer Events only — mouse, finger and Pencil in one path. Today Pro has zero touch* listeners, which is why a drag simply dies on a phone.
