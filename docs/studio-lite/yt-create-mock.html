Pattern study · YouTube Create → Studio Lite

A phone editor is not a small desktop editor

Eight screenshots of YouTube Create's Android editor, read for the decisions underneath them — then rebuilt here as one working phone: switch the canvas ratio, go fullscreen, collapse the text lane into a bar, rotate a clip, pick a Start and a Finish animation, retype the title. Every panel is a real Cancel / Done editor with a live preview, so the state readout under the phone changes when you commit and snaps back when you don't.

The analysis, measurements and phased build plan are in docs/studio-lite/YT-CREATE-PATTERN-PLAN.md, and the reference screenshots this page is derived from are listed in section 3.

1 · The editor, working

Drag the filmstrip to scrub — the playhead stays where it is and the film moves under it, which is the reference's central gamble. Tap a clip to select it. Tap the ⌃ on a lane to collapse it. The rail opens panels; every one of them keeps the preview live and ends in Cancel / Done.

The state the panels edit

One object, read by the preview, the timeline and the panels. Cancel restores the snapshot taken when the panel opened; Done keeps it and pushes one undo entry. This is the same contract as mock.html's one-undo-per-drag rule, applied to property edits.

2 · The four patterns that carry it

        

            Everything else in the reference is decoration. These four are the product decisions, and each one is
            checkable in the phone above.
        


        

            

                
P1 · the preview band

                
Only the preview resizes

                

                    The reference's chrome block — transport, timecode, timeline, rail — occupies the same pixels in the
                    ~1:1 screenshot and the 9:16 one; the preview grew upward from a fixed bottom edge. Ours does
                    the same, and the panel shell is deliberately exactly the chrome block's height
                    (328px) so opening a panel doesn't move the preview either.
                

            


            

                
P2 · pinned playhead

                
Drag the film, not the playhead

                

                    A 2px playhead is a fine mouse target and a terrible thumb target. The reference pins it at the centre
                    and makes the lane area itself the scrub surface. Our version: one pointer gesture, one undo entry on
                    release, and pointercancel ends it cleanly (§5.1). The cost
                    is honest — you cannot see the whole project at once; zoom decides.
                

            


            

                
P3 · collapsing lanes

                
Overlays become bars

                

                    Four 20px lanes spend 80px of a phone's height on three things you are not editing. Our rule: the
                    main video lane never collapses; every overlay lane collapses to a 12px
                    bar — still showing kind, position and extent — with its 44px target intact. This is where the
                    kind-as-texture grammar from mock.html pays off: a 12px
                    waveform is still a waveform.
                

            


            

                
P4 · the panel shell

                
One shell, six bodies, live preview

                

                    Rotation, Start/Finish, Text art, canvas, ratio and the title all wear the same clothes: preview on top,
                    one control group, Cancel (dark) / Done (the only white thing on screen). Snapshot on
                    open, restore on Cancel, one undo entry on Done. The controls are sliders and rings of presets — no
                    numeric fields, no keyframe editor anywhere in the eight screenshots.

4 · Adopt, adapt, refuse

        

            The reference's generative tiles are the clearest example of something we should not copy: they need the
            network, credentials and a model, and they serve none of Studio Lite's three jobs (§2.2).
